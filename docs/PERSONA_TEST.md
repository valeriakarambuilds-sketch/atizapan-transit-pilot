# Week 7 simulated reviewer feedback

This note summarizes the supplied Week 7 feedback using a **simulated 52-year-old operator/authority reviewer**. No real participant was interviewed or observed. The seven screens below are a walkthrough summary of the dashboard sections, not seven separate application pages or a claim of browser testing in this session. No verbatim transcript was supplied; these are paraphrased review points.

| Screen / review step | Simulated review focus |
| --- | --- |
| 1. Pilot overview and timeline | Understand the bounded three-stop proposal and the unequal 14-day baseline and 30-day pilot windows. |
| 2. Wait and crowding summary | Interpret 20 → 17 minutes as 15% less waiting and 48% → 39% as 9 percentage points lower; distinguish an entered zero wait from a missing value. |
| 3. Map and simulated telemetry | Treat the route, stops, GPS, speed and timestamp as invented playback, not confirmed operations. |
| 4. Local ML estimate | Keep the prediction separate from evidence; invented training data provides no validated real-world accuracy. |
| 5. Editable aggregate evidence | Ask for verified sources and appropriate per-day event rates; unequal-window counts cannot establish improvement or causation. |
| 6. Budget and pilot conditions | Require confirmation of the payer and enforcement process while retaining voluntary paid participation, correction rights, independent verification, authority closure and the shadow clause. |
| 7. Human decision | Clarify that Revise requests changes before approving a real pilot, and that a browser-only record is temporary rather than an official audit record. |

The resulting simulated decision was **Revise**: request verified evidence sources, comparable observation coverage, and confirmation of the payer and enforcement process before approving a real pilot. This is a summary of the supplied simulated feedback, not a real authority decision or a decision automatically saved into the app.

The focused usability improvement makes the meaning and limits of this review explicit: Revise is explained beside the control; a zero baseline has a division-by-zero explanation distinct from missing data; event counts have labeled per-day rates; and source, governance and record limitations are visible. Unresolved cases remain an end-of-window backlog count rather than an event rate. The default baseline remains 20 minutes.
